# 试用任务：真实使用两周（v0.8.1 实战检验）

> 建档：2026-11-16（主设备）｜执行设备：另一台电脑｜执行人：仓库主人｜状态：**待开始**

## 这是什么任务（30 秒）

zcode-crosschat 从 v0.1.0 到 v0.8.1 共 15 个版本，所有验收都是**搭出来的测试场景**。"好不好用"的真正判据——**实际干活省没省事**——从未在真实任务上量过。本任务 = **挑一个真实大任务，用本插件协作干两周，每次用完记三个数**。两周后的数据直接决定 v0.9.0 做什么：数据说是 bug 就修 bug，说是摩擦（某步总要手动）就做对应改进，没被数据提到的功能不做（反臃肿原则）。

## 第一步：新设备安装（约 5 分钟）

按 [README「快速开始」](../README.md)三步走：GitHub Release 下载预构建包（`zcode-crosschat-0.8.1-prebuilt-slim.tar.gz`，**保留原文件名**——`.sha256` 按原名录）→ `plugins marketplace add` → `plugins install`。装完在任意会话跑 `xc_doctor`（只读体检）确认健康。

两点预期管理：

- 插件**仅 Windows 实测**（README 已知限制 1）。试用设备若是 macOS / Linux，这本身就是宝贵数据——能跑/不能跑/哪里断，如实记下；
- GitHub 下载不畅的兜底通道见 README FAQ（codeload 源码包，需先构建再添加）。

## 第二步：怎么用（大白话协议）

1. **挑活**：挑一个本来就要做的、会跨天 / 需要多个会话的真实任务。**不用为试用编任务**——真实习惯才能暴露真实摩擦。
2. **开工**：同一工作目录开两个 zcode 会话，各自 `/xc-work <花名>`（小写英文名）。
3. **派活**：主会话 `/xc-dispatch <目标名> <任务描述>`；干活的会话下一回合自动收到，`xc_claim` 认领 → 干完 `xc_report` 带证据回传。日常协作就这一条链。
4. **插话**：只在关心的点说话——让会话 `xc_relay` 带 `urgent:true` 插队，不用等它当前回合跑完。
5. **压缩 / 换会话前**：`/xc-checkpoint` 落检查点；新会话 `/xc-handoff` 接手（≤3 次工具调用进入状态）。
6. **按平时习惯干，别惯着它**：哪里别扭，哪里就是数据。
