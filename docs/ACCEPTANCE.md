验收期发现并修复的缺陷（1 处，既有缺陷、非 v0.5.0 引入）：

- **hold 暂存件无法被 accept 放行**——放行时的「按当前策略重新裁决」没有把收方档类传进裁决函数，于是恒判「收方档类未知 → hold」，因 mode-unknown 被暂存的消息永远放不出来（只到 12h TTL 过期）。修复：裁决前读取收方基记录档类并传入（与首次接收路径同口径）+ 补一条集成回归单测；修复前该用例失败、修复后通过，随后全量单测与全部验收脚本重跑全绿。

其他验收发现（不影响上述五条判定，已在 README「已知限制」与发布说明中照录）：转发链 hop 只记一跳（pipe 通道不累积，溯源主体不受影响）；暂存件放行/拒收后的终态回执到不了发方会话（端点按「status 帧收→发专用」丢弃）；盖章语料是宿主展开后的整段提示文本（含命令模板示例原话）。

验收期环境事实（如实声明）：① 插件由源码构建后**物化到宿主 cache** 供真会话使用，repo `dist/` 与 cache `dist/` 的 sha256 逐文件一致；② 真会话的 peers 根在宿主默认根（`~/.zcode/cli/plugins/data/zcode-crosschat@dev-zcode-crosschat/peers`），与 `ZCODE_PLUGIN_DATA` 无关（该变量对钩子为空）；③ 验收脚本自身的两处取材缺陷（全局 store 历史行污染、回合并发冲突）已按 `fromSessionId` 精确过滤复算，属**验收工具链**问题，插件产品代码不涉及。
