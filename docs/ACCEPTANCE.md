# ACCEPTANCE：验收结论台账（仓内公开版）

- 用途：面向仓库读者的验收结论台账——每个版本「验收了什么、判定如何、关键证据摘录是什么」，一眼可查。
- 口径：完整验收报告与逐条原始证据存于项目工作区的独立证据仓，**不随本仓库发布**（避免把内部环境细节带进公开库）；本台账只保留可公开的结论与证据摘录，不引用任何证据文件路径。
- 环境口径：以下验收均在 Windows 11 + Git Bash 环境完成（**仅 Windows 实测**，其他操作系统未经测试）。
- 维护：每个新版本验收完成后由验收环节回填对应小节；README 的能力宣称与本台账对齐。

## v0.2.0（2026-11-09）：lead-成员协作 · 自动开工 · 动态成员

验收形态：一条人工指令驱动 lead 会话完成「立队 → 程序化创建 3 个成员 → 派发 3 个并行任务」，此后全程无人输入。

| # | 硬标准 | 判定 | 关键证据摘录 |
|---|---|---|---|
| 1 | **自动开工·核心**：lead 派发后，成员会话从「得知任务」到「回传结果」全程零人工输入 | 通过 | 3 个成员的唤醒回合记录均非零且自述全链；引擎审计事件链为 `register(via=wake) → claim → report(in_progress) → report(completed) → idle` ×3；派发方回合内 user 实质输入恰 1 条（其余为宿主注入上下文） |
| 2 | **动态成员**：程序化创建的新成员会话自动投入工作 | 通过 | 3 次 `xc_member_add` 全部经 app-server 建会话 → 设模型 → 欢迎回合自注册（零人工开窗口）；成员名册 `state:"ready", identity:"engine"`；建员后派发直达唤醒投产 |
| 3 | **lead 协调**：≥2 任务并行 + 独立核对 + 汇总 | 通过 | 三成员执行时间窗两两重叠（13.7s / 17.3s / 21.8s）；lead 收 3 条回执 + 3 条空闲通知后，独立读取结果文件核对行数与数值（sha256 复算 3/3 一致），输出最终汇总 |
| 4 | **回归**：pull 邮箱闭环 + 全量单测 | 通过 | pull 三环冒烟通过且引擎审计 0 条唤醒行（wake 关闭正确回落邮箱）；全量单测 24 文件 / 294 例全绿；typecheck 零错误；manifest 校验通过；v0.1.0 旧数据在新版本下照常读写 |
| 5 | **能力差距闭合**：核心差距逐条闭合，无未经实验证据的平台限制宣称 | 通过 | 六项核心差距（lead 协调 / 事件驱动自动开工 / 动态成员 / 并行与上限 / 进度可视 / 消息安全）逐条对账闭合；控制与安全演示通过（状态全景、任务取消、成员停止、未知帧拒收、入站 hold/refuse、冒名注册被拒） |

补充实测（同一验收内）：CLI 单发派发方退出后，成员仍全自动完成任务（唤醒子进程经孤儿化跳板存活）——派发方生命周期不再影响已派发任务。

验收期发现并修复 1 个插件实现缺陷（如实声明）：成员供给时未应答宿主的运行时偏好请求，导致建员 15s 超时失败——端到端真实运行暴露、单测未覆盖；最小修复后全量复测全绿。另记录 1 次环境操作事故（卸载命令清空了插件设置项），属操作事故、非插件缺陷。

## v0.3.0（2026-11-09）：跨会话消息轴（peer 轴）

验收形态：两个**互无团队关系**的独立会话（不同工作区）全程程序化互发消息；另有 7 个真实 MCP server 进程做入站策略矩阵。验收对象为强制重新物化所用的工作区版本（0.3.4），发布定稿 = 同一代码树的 tag `v0.3.0`。

| # | 硬标准 | 判定 | 关键证据摘录 |
|---|---|---|---|
| 1 | **跨会话消息闭环** | 通过 | A→B 与 B→A 双向回执 `delivered`（命名管道通道）；消息 id 在两侧审计日志中成对串联（无人工搬运反证）；两工作区均无队内任务板/邮箱痕迹（第二通道独立性反证） |
| 2 | **peer 发现** | 通过 | 可寻址清单一次给出跨工作区的多个会话（含未入队会话）；未注册会话不在发现集（负证如实记录）；重名不猜——返回 `ambiguous` + 候选行，带 `[ref]` 精确命中 |
| 3 | **入站三态** | 通过 | 12 个策略用例全过：accept / hold（模型不可见）/ 人工放行 / refuse / 显式层最严胜 / 非法取值 fail-closed / kill-switch / 自动档四态 + 自动档可达性反证 |
| 4 | **观测面板** | 通过 | 一次 `xc_agents` 调用给出 self / peers / members / tasks / 当前入站策略全景；斜杠命令 `/xc-agents` 注册在列 |
| 5 | **回归（v0.2.0）** | 通过 | typecheck 零错误；全量单测 36 文件 / 509 例全绿（默认并发连跑 5 次）；v0.2 自动开工冒烟 3 任务 sha256 独立复算全 MATCH；pull 邮箱闭环 0 条唤醒行；队内域文件零改动（diff 为空） |
| 6 | **平台限制条款** | 通过 | README 已知限制逐条带证据出处；未实测项一律标「未确认」而非宣称限制 |
| 7 | **信封呈现** | 通过 | 三个消费面（钩子注入 / 工具结果末尾块 / 显式拉取）均实证到注入原文；归因尾注 6 项全中；正文内嵌的伪造信封标签被剥离、`@` 引用不展开 |

验收期发现并修复 3 个真实产品缺陷（修复前均先复现留证，均补回归用例）：

1. **注册表心跳缺失**——注册记录 60s 后被当作失联清扫，对方报「找不到会话」；修复为 15s 周期心跳 + 优雅退出摘记录。
2. **peer 工具结果不携带信封块**——回合内调 peer 工具时到达的消息不注入；修复为统一在工具结果末尾追加信封（原有内容逐字节不变）。
3. **发送方收到不合法帧时死循环**——对端发一行垃圾帧即可卡死本会话事件循环（安全相关）；修复为先推进游标再处理。
